## 0. 设计约定

### 0.1 节点编号
- 节点 ID `#N` (N ∈ 1..30) 与问卷 Q# **完全对齐**
- 节点名 = 问卷题面 `[节点: XX]` 标签

### 0.2 极性方向
- `#N+` = Likert **5–6 分侧** 的立场（赞同尖锐陈述）
- `#N-` = Likert **1–2 分侧** 的立场（反对尖锐陈述）
- `#N` 单独出现 = 该轴上中立 (3–4 分)，不激活任何有向节点
- 节点总数 (有向): 30 × 2 = **60 节点**

### 0.3 分档规则 (Likert 1–6 → 三档极性)

| Likert 分数 | 极性 tier | 用途 |
|---|---|---|
| 1–2 | `-` | 反对侧明确；激活 `#N-` 节点 |
| 3–4 | `0` | 中立/弱倾向；不激活任何有向节点 |
| 5–6 | `+` | 赞同侧明确；激活 `#N+` 节点 |

阈值后续可基于数据分布调整（见 §4 待定项）。

### 0.4 Dual-track 渲染格式
所有 prompt / GT 中对 SADR 节点的引用统一使用 `{id, label}` 双轨：
```json
{"id": "#3+", "label": "AI 替代主义"}
```
让 Qwen 借预训练词义 (label) 与稳定标识 (id) 同时 reason。

## 2. 字段 schema (派生输出)

### 2.1 `profile_30d` (raw)
30 个 1–6 分原值，index 与 `#1`–`#30` 对齐：
```json
"profile_30d": [4, 2, 6, 5, 3, 1, 4, 6, ..., 5]   // 长度 = 30
```
用途: Task A/B 输入信号、个体 RAG 索引、cluster centroid 派生。

### 2.2 `derived_sadr_30` (polarized)
30 条 per-axis 极性结果，永远 30 条 (含 polarity=0)：
```json
"derived_sadr_30": [
  {"axis": "#1", "polarity": "+", "label": "重直觉立场",       "raw_score": 6},
  {"axis": "#2", "polarity": "-", "label": "后天努力论",       "raw_score": 2},
  {"axis": "#3", "polarity": "0", "label": null,             "raw_score": 4},
  {"axis": "#4", "polarity": "+", "label": "技术激进主义",     "raw_score": 5},
  ...
]
```

**渲染规则**:
- `polarity ∈ {+, -}` → 渲染为 dual-track `{id: "#N±", label: "<立场名>"}`
- `polarity = "0"` → 默认**不进 prompt**（ontology 检索 top-k 自然过滤）；如需"该 designer 在此轴中立"信号，单独字段 `neutral_axes: ["#3", ...]` 标注

用途: Task A 输入、ontology 检索 query、dual-track GT 渲染。
