# PKVC Extractor Prompt v7f (v7e + 典型句式 marker)

> v7f vs v7e: v7e 4 段 fail case (V3 设立原则被判 C / P3 推翻被判 V) 的根因是 prompt
> 给了 12 cardId 关键词但没给**典型句式 marker**, LLM 不知道"原文长这样 = 这个动作".
> v7f 加 4 个高频子类 (V3 / P3 / K2 / C1) 的典型句式 + 易混淆反例.

---

## System Prompt

```
你是设计师认知分析专家. 任务: 从设计师 Q7 思维链段落中提取 PKVC 主导因子 + 核心底线.
严格输出 JSON, 只 4 个字段, 不要 markdown 围栏 / 不要解释.

铁律:
1. **criterion (非 null) 必须 verbatim 节选自 INPUT BEGIN/END 区段**, ≤ 20 字.
2. **dominant_factor 必填非 null**. 即使 confidence=low, 也给最可能的字母或路径.
3. JSON 字段名严格: dominant_factor / criterion / confidence / extraction_notes.
4. 只 4 字段, 不要加 cardId / o_primary / p_surface 等额外字段.
5. P/K/V/C 4 类都是 valid 选项 — 不要默认所有段都是 V.
6. ⭐ **优先识别"高 surface marker"句式** (见下方典型句式表): V3 设立原则 / P3 推翻假定
   有最明显的语言信号, 看到就强 weight.
```

---

## User Prompt Template

```
# 任务

从 INPUT BEGIN/END 区段的设计师 Q7 思维链中提取 PKVC 主导因子 + 核心底线.

# 输入 metadata (LLM 不要 echo)

- segment_role: {SEGMENT_ROLE}
- scenario:     {SCENARIO}

# PKVC 4 因子 + 12 子类 (用作识别提示, 不输出)

| 大类 | 子类 (识别用, 不输出) | 触发关键词 |
|---|---|---|
| **P** Problem | P1 界定核心 / P2 拆解子问题 / P3 推翻假定 | 底线, 真实问题, 拆解, 推翻, 根本不在这里, 重新定义 |
| **K** Knowledge | K1 调用经验 / K2 客观数据 / K3 评估技术栈 | 案例, 经验, 竞品, 数据, 报告, 证明, 技术栈, 调研 |
| **V** Value | V1 价值立场 / V2 利益排序 / V3 设立原则 | 个人偏好, 主观, 利益冲突, 排序, 绝对, 不可牺牲, 原则 |
| **C** Concept | C1 涌现画面 / C2 整合构建 / C3 提炼原则 | 脑海, 画面, 形态, 收敛, 整合, 概念方案, 提炼 |

# ⭐ 高 surface marker 典型句式 (看到就强 weight)

| 子类 | 典型句式 marker (verbatim 句式特征) | 易混淆反例 |
|---|---|---|
| **V3 设立原则** | "我的底线是 X" / "最核心的设计底线" / "我向上层提的底线" / "X 是不可妥协的" / "无论如何 X" / "最大前提是 X" / "首要原则是 X" | 段中讨论"X 重要"≠ V3; V3 是宣言式收束, 一般在段首或段尾; "X 是关键" 是弱 V 不是 V3 |
| **P3 推翻假定** | "不是 X 而是 Y" / "其实问题不是这样" / "别把 X 看成 Y" / "我觉得这两个并不矛盾" / "这个问题应该重新定义" / "除非重新 X" / "问题本身可能错了" | "我同意 X 但 Y" 是 V2 利益排序, 不是 P3; "X 跟 Y 各有道理" 是中立, 不是 P3 |
| **K2 数据驱动** | "需要调研" / "用数据决定" / "看 A/B 测试" / "X% 转化率" / "用具体的经营数据来决定" / "我得先了解 X" | "我觉得数据告诉我们 X" 但后面没真用数据 → 不是 K2; K2 是把判断真正延后到数据 |
| **C1 涌现画面** | "脑海里画面是 X" / "有趣且兴奋" / "历史性意义" / "想想就觉得 X" / "我希望它长得像 X" | 仅描述具体方案细节是 C2 整合, 不是 C1 画面 (画面是兴奋/愿景, 不是落地方案) |

⭐ **优先级**: 段内出现以上 marker 时, dominant_factor 应强烈倾向对应子类的大类.
例如段首"最核心的设计底线" → V (V3), 不要被段中"AI 地图""调研"等次级信号带跑.

# ⚠ 常见误判 (来自 v6/v7 历史 case)

- "需要调研" → K (不是 P; P 是质疑问题框架)
- "成本至上"作底线: V 先行 = V 主导; K 搜索后浮现 = K 主导
- 第一句"直觉" 不一定 V — 看后续是 P3 推翻 (D seg1) 还是 C1 画面 (F seg1) 还是 V 立场
- 兴奋"这有趣 / 历史性意义" = C1 入口 (不是 V)
- "不是 X 而是 Y" / "并不是二选一" = P3 推翻 (不是 V 也不是 C)
- "段首明确宣告底线" = V3 (即便段中有 C/K 次级信号, dominant 仍 V)

# 输出 Schema (4 字段, 字段名严格)

- `dominant_factor`: 必填非 null. "P" / "K" / "V" / "C" 或路径如 "K→V" / "P→C" / "C→P"
- `criterion`: ≤20 字 verbatim INPUT 节选, 或 null
- `confidence`: "high" | "medium" | "low"
- `extraction_notes`: 一句话总结 ≤ 30 字, 指明触发的 marker 或主导子类

⚠ 严禁字面输出 prompt 中固定串作 criterion ("需要调研老城区居民" 等).

# 四个 few-shot 示例 (K/P/V/C 各 1)

## 示例 1 — K 主导 (K2 数据驱动)

INPUT (附录 C seg1):
> 我的第一反应是, 这个老城区的主要用户群体是什么? 如果大部分是年轻人或者追求
> 效率的打工人, 那第一个问题没啥; 如果大多数是老年人, 那需要考虑拆除之后老年
> 人是否还愿意来这个超市? 是否会对这个超市的营收带来影响? 这些都是需要调研的.

marker: "这些都是需要调研的" = K2 数据驱动入口.

Output:
{
  "dominant_factor": "K",
  "criterion": null,
  "confidence": "high",
  "extraction_notes": "K (K2 数据驱动): 段尾'需要调研'明确"
}

## 示例 2 — P 主导 (P3 推翻假定)

INPUT (附录 D seg2):
> 首先这个方案影响最大的客群就是老年人, 那么我需要知道老年人口的比例? 老年
> 人除本超市外是否有可替代的选择? 这些问题综合考虑起来才有价值讨论是否应该
> 放弃部分老年客户. 零售行业面向不同的客群可以做精细化的、定制化的转型. 不
> 同的商超本来就有不同的客群, 每一类服务一类客群、服务好即可. 至于诱导和操
> 纵? 商业算法本来就是引导和欺诈来赚取更多利润, 除非重新定义商业行为.

marker: "每一类服务一类客群" (推翻"放弃 vs 保留"二元) + "除非重新定义商业行为"
(P3 推翻终极假定) = P 主导.

Output:
{
  "dominant_factor": "P",
  "criterion": null,
  "confidence": "high",
  "extraction_notes": "P (P3 推翻): 重构客群划分 + 段尾'重新定义商业行为'"
}

## 示例 3 — V 主导 (V3 设立原则)

INPUT (附录 E seg3):
> 给人用的东西, 最大的前提是尊重用户, 最首要的功能是服务用户. 你要做便民项目,
> 那你的前提是便民, 而不是炫耀你的技术. 如果你要牺牲用户去换这些短期收益, 那
> 迟早会崩盘. 我会觉得这种东西最核心的是让人幸福、而不是得利.

marker: "最大的前提是 X" + "最核心的是 X" = V3 设立原则.

Output:
{
  "dominant_factor": "V",
  "criterion": "让人幸福而不是得利",
  "confidence": "high",
  "extraction_notes": "V (V3 设立原则): 段首'最大前提' + 段尾'最核心是让人幸福'"
}

## 示例 4 — C 主导 (C1 涌现画面 → P3 推翻)

INPUT (附录 F seg1):
> 关于这个项目, 零售巨头希望在老城区做一个全国首个全数字化、无人化的高效零售
> 标杆, 我觉得有趣且兴奋, 它带有历史性的意义. 关于三个矛盾, 我想先说最后一个
> ——第三点: 面对抗议和质疑, 上层认为 3 个月内必须按数字化方案铺开, 这是公司
> 战略, 不能为了少部分人牺牲新贵的极致体验. 我觉得这两个并不矛盾. 首先, 我会
> 非常愿意去尝试做这样的一个数字化方案的铺开; 而且在这个铺开的过程中, 并不会
> 牺牲年轻新贵的极致体验, 完全是可以共存的.

marker: "有趣且兴奋 + 历史性意义" = C1 涌现画面入口; "我觉得这两个并不矛盾" + "完
全是可以共存的" = P3 推翻"二选一"假定.

Output:
{
  "dominant_factor": "C→P",
  "criterion": null,
  "confidence": "high",
  "extraction_notes": "C (C1 画面感) → P (P3 推翻'二选一')"
}

# 输出前 self-check

Q1: 段内有没有 V3 marker ("我的底线" / "最核心的" / "不可妥协")?  → V 主导
Q2: 段内有没有 P3 marker ("不是 X 而是 Y" / "推翻 / 重新定义")? → P 主导
Q3: 段内有没有 K2 marker ("需要调研 / 用数据决定 / 看转化率")? → K 主导
Q4: 段内有没有 C1 marker ("有趣 / 历史性 / 画面 / 兴奋")? → C 主导
Q5: dominant_factor 非 null? criterion verbatim 在 INPUT?

# ========== INPUT BEGIN ==========

{INPUT_TEXT}

# ========== INPUT END ==========

# 现在严格输出 JSON, 只 4 字段
```
