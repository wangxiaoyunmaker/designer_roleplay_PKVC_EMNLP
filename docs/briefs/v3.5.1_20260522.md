# v3.5.1 完整技术方案(Trait Layer × CAPS theory × PKVC State Machine 三层架构)

> **核心 claim**:用 200 designer 真实问卷数据训练 LLM 做 **cluster-level cognitive trajectory role-play**, 通过 **(a) 30 维 trait layer 测量 designer 的 CAPS network weights** + **(b) PKVC 4 状态运行时 state machine** + **(c) trait-state modulation triple (本工作 operationalize CAPS theory)** + (d) 簇内 peer RAG + (e) cluster-contrastive SFT, 实现 **cross-scenario PKVC trait 迁移**。

> **v3.5.1 vs v3.5 delta (framing 修正, 当日内)**:
> ㉘ **修正 CAPS 定义**: CAPS 是 Mischel 1995 *理论* (trait modulates state-transition 机制), **不是 30 维量表本身**. 30 维是 "CAPS theory 指导下测量出来的 designer 个人 network weights".
> ㉙ **修正 PKVC 定位**: PKVC 是 **处理状态机** (4 状态 P/K/V/C 运行时引擎), **不是输出行为层**. SADR 30 节点是 4 状态的子细分.
> ㉚ **修正 bridge 表述**: 不是 "CAPS→PKVC mapping", 是 "30 维 trait modulates PKVC state-transition probabilities", 引用 introduction 里 `<Data-Driven Belief, Strong-Inhibit, Concept-Phase>` 形式.
> ㉛ **修正 triple schema**: source 改 multi-dim **trait pattern** (从 EFA factor loadings 取), target 改 **PKVC 4 states (P/K/V/C)** 不是 SADR node, 加 **modulation 4 档** (Strong/Weak × Inhibit/Excite) + Bypass flag.
> ㉜ **修正 mining 算法**: 从 "co-occurrence" 改 "**distribution shift detection** (permutation test on state activation distribution)", 公式 Δ = P(state | trait_pattern) − P(state | population).

> **v3.5 vs v3.4 delta (本次 12 条 locked-in)**:
> ⑯ Cluster 特征锁定 **30 维 CAPS only** (拒 30+Q1-Q6 因 target leakage + 部署不可行)

### 4A.4 Loss

```
L_total = L_B1 + L_B2 + L_B3 + 0.3·L_cc + 0.2·L_cls

L_cc anchor:  Task B3 response 末端 hidden state
L_cls anchor: prompt 末端 hidden → linear classifier (K-way) → cluster_id
```

### 4A.5 Curriculum

```
前 33% steps: L_B1 + 0.3·L_cls       (第一反应先收敛)

后 33% steps: + L_B3                  (加底线)
```

### 4A.6 推理

```
Step 1: prompt → [INTUITION]
Step 2: prompt + Step1 → [WEIGH]
Step 3: prompt + Step1 + Step2 → [BOTTOM_LINE]
```

## 4D. Trait-State Modulation pipeline (v3.5 NEW, v3.5.1 framing 修正)

### 4D.1 动机 (修正版)

```
Trait Layer:        30 维信念量表 = designer 个人 CAPS network weights (静态)
                    EFA → 4-5 个 factor (e.g., "数据驱动倾向", "概念发散倾向")
PKVC State Machine: P/K/V/C 4 状态处理引擎 (运行时), 30 SADR 是子细分

CAPS theory 主张: trait 通过改变瞬时状态影响行为 ("If [trait+context] Then [state activation]")
→ 不是 trait 静态映射到行为, 是 trait 动态调节 state-transition 概率

v3.4 默认 RAG: 同簇 peer 整段 Q1-Q6/Q7 segment → 模型从具体例子归纳
v3.5 新增 RAG: 该 designer 的 trait pattern 在 PKVC state machine 上的 modulation 规律 (从 train fold designer 群体里挖)
  → 直接 operationalize CAPS theory 的 If-Then 机制
  → 比 peer mimicry 更接近 cognitive theory 的因果 claim
  → 减少 rationalization (peer answer 模仿) 风险
  → 跟 introduction 里 <Data-Driven Belief, Strong-Inhibit, Concept-Phase> 表述一致
```

### 4D.2 Triple schema (修正版)

```yaml
mapping_triple:
  source:
    factor_id:    "F2"                # EFA factor index (200 入袋 EFA 后定)
    factor_name:  "数据驱动倾向"        # 学姐 + 你给 factor 命名
    direction:    "high" | "low"      # designer 在该 factor 上是 high/low score
    composition:                       # Fine ablation 用, v1 留空
      - {factor_id: F2, direction: high}
      - {factor_id: F4, direction: low}
  modulation:
    type:    "Strong-Inhibit" | "Weak-Inhibit" | "Weak-Excite" | "Strong-Excite"
    bypass:  false                     # true: PKVC state 完全跳过 (extreme Strong-Inhibit)
    delta:   -0.42                     # 原始 Δ = P(state | trait_pattern) − P(state | population)
    p_value: 0.012                     # permutation test (n=1000 shuffles)
  target:
    pkvc_state: "P" | "K" | "V" | "C"  # PKVC 4 状态之一, NOT SADR node
  context:
    scenario_type: "服务重构"          # 可选, 留 fine ablation 用 (v1 默认 null = scenario-agnostic)
  cluster_id: 3                         # per-cluster mining 时填; null 表示 global
  support:    12                        # 多少 designer 在该 trait pattern 内贡献
  fold_id:    0                         # 该规则属于哪个 train fold
```

**4 档 modulation 跟 trait 4-bucket polarity 对称**:

| modulation | Δ 范围 | 跟 trait polarity 类比 |
|---|---|---|
| Strong-Inhibit | Δ < -0.3, p < 0.05 | 类比 strong- |
| Weak-Inhibit | -0.3 ≤ Δ < -0.1, p < 0.05 | 类比 weak- |
| Weak-Excite | 0.1 < Δ ≤ 0.3, p < 0.05 | 类比 weak+ |
| Strong-Excite | Δ > 0.3, p < 0.05 | 类比 strong+ |
| (不 emit triple) | \|Δ\| < 0.1 或 p ≥ 0.05 | baseline |
| Bypass (flag) | Δ ≈ -1.0 (该 trait 下从未激活) | strong- 的极端 |

### 4D.3 Mining 算法 (distribution shift detection, 修正版)

**方案 A (statistical distribution shift, 主)**:

```
准备:
  - 每 designer 算 PKVC state activation distribution: (p_P, p_K, p_V, p_C), 各加起来 = 1
    来源: Q1 priority + Q2 trajectory + Q3-Q6 conflict choice + Q7 segments factor / factor_path
    每 designer 累积所有 PKVC event count, 按 state 归一化
  - 每 designer 算 EFA factor scores (从 user_factor_scores.csv 取)

per fold (k = 0..4):
  train_users = fold[k].train_user_ids       # 160 designer
  baseline_rates = mean(state distribution across train_users)   # 4-dim vector

  for factor_id F in {F1, F2, ...}:
    median_score = median(train_users.factor_scores[F])
    high_group = train_users.where(factor_score[F] > median_score)
    low_group  = train_users.where(factor_score[F] ≤ median_score)
    
    for direction in {high, low}:
      group = high_group if direction == high else low_group
      group_rates = mean(state distribution across group)   # 4-dim
      
      for state s in {P, K, V, C}:
        delta = group_rates[s] - baseline_rates[s]
        if |delta| < 0.1:
          continue  # 不显著, 不 emit
        # permutation test: shuffle factor_score[F] 1000 次, 看 shuffled |delta| 多少次 ≥ observed
        p_value = permutation_test(factor_scores[F], state_dist[s], n=1000)
        if p_value >= 0.05:
          continue
        # 分档
        modulation_type = bucket(delta)      # 4-档
        bypass = (group_rates[s] < 0.05)     # 几乎从未激活
        emit triple(source={F, direction}, modulation, target=s, ...)
  
  per-cluster 模式: 在 designer cluster c 内重复上面循环, cluster_id = c 写入 triple
  global 模式: 全 train_users 一次, cluster_id = null

过滤: support ≥ 10 (该 trait pattern 内 designer 数), p < 0.05
```

**方案 B (LLM abstraction, 辅助 audit)**:

```
对每个 designer cluster, 抽 20 designer 喂 GPT-4o:
  context = [factor_scores 概览 + Q1-Q6 答案 + 解释 NL + Q7 三段]
  prompt = "用 <factor pattern, modulation, PKVC state> 格式描述这群人的认知风格"
  → 解析输出, 跟方案 A 同 cluster 输出 cross-check
  → κ ≥ 0.7 (跟 extractor κ pilot 同 audit pipeline)
  → 不作为单独 mining path, 仅用于 audit + sanity
```

- Path α (反): 替换 peer, 失去具体例子
默认 γ, ablation 比 β.

### 4D.6 Mining fold-awareness (防 leakage)

```
5-fold CV:
  for fold in 0..4:
    train_users = fold.train_user_ids       # 160 designer
    test_users = fold.test_user_ids         # 40 designer (含 test 评测对象)

    modulations = mine_modulation_triples(
        designer_factor_scores[train_users],
        designer_state_distributions[train_users],
        cluster_file=user_cluster_efa_v2_200.csv,
        fold_id=k,
    )
    → modulation_fold_{fold}.jsonl

  → 测试 fold k 的 designer 时, 用 modulation_fold_k.jsonl 注入 prompt
  → modulation 里没有 test designer 的 state distribution 信号, 不 leak target
```

**关键**: modulation 必须 per fold rebuild, 不能跑一次全员 mapping 用 5 折 (会 leak).
