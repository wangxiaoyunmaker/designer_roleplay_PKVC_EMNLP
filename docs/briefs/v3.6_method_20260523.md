## 1. Framing — 三层架构 (防漂锚)

```
┌─ Trait Layer (静态) ──────────────────────────────────────────┐
│  30 维领域信念量表 = designer 个人 CAPS network weights         │
│  EFA → 4-5 trait factor (无名 F1-F5)                           │
│  K-means K=6 cluster (待 N≥200 重锁; 现 N=133 best K=7 但      │
│       min_size=3 不健康, 强锁 K=6 保 brief framing)            │
└────────────────────────────────────────────────────────────────┘
                              │
                              │  CAPS theory (Mischel & Shoda 1995):
                              │  连接机制, 不是 layer
                              │  If [trait factor pattern + situation C]
                              │  Then [state activation in PKVC]
                              ▼
┌─ Bridge Layer (动态, NEW main candidate) ─────────────────────┐
│  T_CAPS = (C_local, s, p, o) 四元组                            │
│  operationalize CAPS if-then 为可挖掘 quad                     │
│  conditional 升级: og_rag+modulation > og_rag-only > 1% →      │
│       main framing 从 "trait→state modulation" 升级为          │
│       "situation-conditioned cognitive routing"                │
└────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─ PKVC State Machine Layer (运行时, 4 状态) ───────────────────┐
│  P (Problem-framing) / K (Knowledge-retrieval)                 │
│  V (Value-judgment)  / C (Concept-generation)                  │
│  30 SADR 节点 = 4 状态的子细分                                  │
│  ground-truth label = LLM extractor 从 Q1-Q6 / Q7 NL 抽出       │
└────────────────────────────────────────────────────────────────┘
```

**防漂硬规则** (来自 framing_correction):
- trait factor (EFA 出的) ≠ PKVC state
- K-means cluster ≠ PKVC label
- 30 维量表 ≠ CAPS (前者是测量结果, 后者是连接理论)
- PKVC 4 状态 ≠ "输出行为层" (是推理过程穿越的状态机)

## 3. 4 层 contamination hold-out (方向二)

| Level | Hold-out 内容 | 防御什么 |
|---|---|---|
| L1 target 标签 | Q7 三段 NL 抽出的 PKVC trajectory ground truth | 直接答案泄露 |
| L2 target 输入 | Q7 题面不进训练 prompt (但进 C_local codebook 抽取, 不算泄露) | 输入分布泄露 |
| L3 同场景 peer | 其他 designer 的 Q7 不进 train fold 的 RAG 池 | peer 答案泄露 |
| L4 任务格式 prior | 3 段 CoT (INTUITION/WEIGH/BOTTOM_LINE) 格式不在训练 output 出现 | 格式 prior 学到 |

**fold split**:
- 5-fold stratified CV 按 `cluster_id` (K=6)
- 当前 N=133 → ~27 test / 106 train per fold (目标 N=200 → 40/160)
- test designer **完全**不进 train fold 的 quad DB / RAG 池 / EFA factor 算 (factor 跨折共享 OK, cluster_id 跨折共享 OK — 只屏蔽 Q1-Q7 NL/答案 + quad)

## 4. T_CAPS v1.1 quad schema (今日锁)

```
T_CAPS = (C_local, s, p, o)
C_global 进 prompt narrative (常量, 不入 quad)
```

| 字段 | 子字段 | 取值 / 词表 | 来源 | 用途 | 例 |
|---|---|---|---|---|---|
| **C_local** 局部情境 | — | 闭集 ≤ 8 tag, `[High/Low]_X_field_[Name]_vs_[High/Low]_Y_field_[Name]` | Q1-Q8 题干 (⚠ 不是 designer 答案) | RAG 过滤 + if-then 表达 | `High_P_Authority_Mandate_vs_High_V_User_Harm` |
| **s** 潜在特质 | `s_primary` | 30 维 high-score tag 集合 | 30 维量表 top-k | RAG 检索 key (Jaccard / cosine) | `{"救世主情结", "弱势群体优先"}` |
|  | `s_secondary` | (factor, direction) 5 × 2 | EFA 4-5 因子 + 方向 (由 s_primary 经 factor scores 自动算) | mining (permutation test) | `(F_共情关怀, +)` |
| **p** 路由谓语 | `p_modulation` | 闭集 5 档 `{Strong+, Weak+, Weak-, Strong-, Bypass}` | 由 `p_surface` 经 codebook 查表 | mining (统计可枚举) | `Strong+ Bypass` |
|  | `p_surface` | 开放词表 8 词 | Q1-Q6 NL LLM 抽取 | paper 写作 + stance 编码 | `defiant_overrides` |
| **o** 目标 PKVC 状态 | `o_primary` | 闭集 4 个 `{P, K, V, C}` | Q1-Q6 NL LLM 抽取 | quad target (main mining) + 评测 | `V` |
|  | `o_subtype` | 闭集 12 个 `{P1-P3, K1-K3, V1-V3, C1-C3}` | 学姐 Q3-Q6 选项-cardId mapping | attribute (不参与 mining); 200 入袋后重评估是否升 primary | `V1` |

### 4.1 `p_surface` ↔ `p_modulation` codebook v0

| surface_predicate | modulation | 隐含 stance |
|---|---|---|
| `forces_transition_to` | Strong+ | neutral |
| `severely_overrides` | Strong+ Bypass | neutral |
| `defiant_overrides` | Strong+ Bypass | Defiance |
| `gradually_shifts_to` | Weak+ | neutral |
| `compliantly_follows` | Weak+ | Compliance |
| `negotiates_around` | Weak+ / Weak- | Negotiation |
| `weakly_inhibits` | Weak- | neutral |
| `bypasses` | Bypass | neutral |

**设计原则**: surface 对外 (paper + LLM 抽取目标), modulation 对内 (mining 统计), 多对一锁死。stance 色彩 (Defiance / Compliance / Negotiation) 编码进 surface 词, **不开独立 attribute 字段** (替代砍掉的 `o_attribute`)。

## 5. 数据加工 pipeline

### 5.1 Q1-Q6 yaml (per designer)

```yaml
designer_id:    <wechat_id>
cluster_id:     <0..K-1>  # 当前 K=6
fold:           <0..4>
profile_30d:
  numerical:    [s1, s2, ..., s30]            # 6-point Likert
```

### 5.3 T_CAPS quad DB (per fold, fold-aware)

```python
for fold_k in 0..4:
    train_users = fold[k].train  # 当前 ~106, 目标 160
    for user in train_users:
        for q in [Q1..Q6]:
            quad = {
                "designer_id": user.id, "question_id": q, "fold": fold_k,
```

### 6.1 prompt 装配 (Path γ system injection)

```
<|system|>
PKVC 框架定义: P=问题界定, K=知识调用, V=价值裁决, C=概念生成
当前 designer 属于 cluster {cluster_id}, 该簇调节规律 top-3:
  - (s={F_共情, +}, p=Strong+ Bypass, o=V) [support=18/22, p<0.01]
  - (s={F_理性, -}, p=Weak-, o=K) [support=14/22, p<0.05]
  - ...
                 ↑ 这就是 Path γ: 从该 fold 的 quad DB 查该 cluster 的 mining 结果
                 ↑ 注: prompt 里塞的是 (s_sec, p_mod, o_pri) 3 元 (C 已经在 [Question] 段
                       由 C_local tag 单独提供, 不重复). T_CAPS schema 仍是四元组.

<|task_background|>
{C_global narrative, 50-100 字, 学姐补}

<|profile|>
该设计师 30 维信念极性: 强+ 探索性, 弱- 规范性, ...  (4 档 NL)

<|peers|>
[同簇 train fold cosine/og_rag top-3 peer 的 Q1-Q6 + 解释 NL]

<|question|>
[Question Q{i}]
C_local: {C_local_tag}
题目: {题面}
选项: {A/B/C/D 或 12 cardId}

<|response|>
[PKVC 分析]
此题测试: {C_local 翻译成自然语言}
该设计师表现: {学到的 explanation_nl style}
[/PKVC 分析]

[答案]
{Q1/Q3-Q6: 单字母 | Q2: cardId 排序 → 聚合 PKVC 路径}
[/答案]
```

### 6.2 模型 + LoRA

```
Backbone:        Qwen2.5-7B-Instruct
LoRA:            r=32, alpha=64, dropout=0.05
target_modules:  [q_proj, k_proj, v_proj, o_proj]
lr=1e-4, batch=20 (cluster-balanced K×ceil(20/K)), 5 epochs, warmup=100, bf16
max_seq_len=4096, gradient_checkpointing=True
```

### 6.3 Loss

```
L_total = L_pkvc + L_answer + 0.3·L_cc + 0.2·L_cls

L_pkvc    token CE on [PKVC 分析] NL          信号源: 设计师真实 explanation_nl
L_answer  token CE on [答案]                  Q1/Q3-Q6 单字母 / Q2 cardId 排序
L_cc      cluster-contrastive on response 末端 hidden (P-React 风格)
                                              同 cluster pull / 异 cluster push
L_cls     K-way classifier on prompt 末端 hidden → cluster_id
                                              内化 trait 信号
```

Curriculum: **无** (per-question single-step 无段间依赖, 所有 loss 同时开启)。

| 项 | 当前 (N=133) | 目标 (N=200) |

| 总样本 | 133 × 6 × 3 (profile noise) = 2394 | 200 × 6 × 3 = 3600 |

**意义**: 同分布强但跨场景 Q7 弱 → fallback 触发信号 (模型学到 task-specific 而非 trait 抽象)。

## 11. Mapping mining 算法 (per fold)

### 11.1 方案 A (statistical, 主)

```python
# 每 fold 独立跑, train_users only
for factor F in EFA_factors:                 # 4-5 个
    high_group, low_group = median_split(train_users, F)
    for state s in {P, K, V, C}:
        baseline_rate[s] = P(o_primary == s | all_train_users)
        high_rate[s]     = P(o_primary == s | high_group)
        low_rate[s]      = P(o_primary == s | low_group)
        Δ_high = high_rate[s] - baseline_rate[s]
        Δ_low  = low_rate[s]  - baseline_rate[s]
        for (group, Δ, direction) in [(high, Δ_high, '+'), (low, Δ_low, '-')]:
            if abs(Δ) < 0.1: continue
            p_val = permutation_test(factor_score, o_dist, n=1000)
            if p_val >= 0.05: continue
            emit_quad(
                C=None,                       # step 1 不带 C, step 2 再加 moderator
                s_secondary=(F, direction),
                p_modulation=bucket(Δ),       # |Δ|≥0.3→Strong, else→Weak; sign→±
                o_primary=s,
                support=len(group),
                p_value=p_val,
            )

# per-cluster 模式 (默认): 每 cluster 独立跑 (当前 22/cluster, 目标 33/cluster)
# global 模式 (ablation): 不分 cluster

# 过滤: support >= 10, p < 0.05
```

### 11.2 方案 B (LLM abstraction, audit)

抽 20 designer/cluster 喂 GPT-4o, 让它直接解析 → quad list, 跟方案 A cross-check κ ≥ 0.7。

### 11.3 hierarchical 拆分 (4 元稀疏防御)

```
step 1 (main):       (s_secondary, p_modulation, o_primary) 三元挖, 数据密度 3.75 quad/cell
step 2 (moderator):  对 step 1 挖到的每条 pattern, 检验 C_local 是否对 P(o|s,p) 有 distribution shift
                     用 stratified permutation by C_local
```

⚠ **不用 o_subtype (12 子类) 跑 mining**: 数据密度 1.25 quad/cell, permutation power 边缘; 200 入袋后 2.5 quad/cell 再重评估。
